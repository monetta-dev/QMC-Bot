# 鳩当番 | QMC

鳩係向けのスマホ対応Webアプリ。LINEでログインし、月間当番表を作成・共有すると、共有済みの担当者へ当日08:00（日本時間）に公式LINEから個別通知します。

実際のLINEで試す場合は、[鳩当番のテスト手順](./鳩当番のテスト手順.md)を参照してください。

## 構成

- Cloudflare Worker 1つ、D1データベース1つ、Cron Trigger 1つ。
- 画面はHTML・CSS・JavaScript。サーバーもJavaScript ES Modules。実行時のnpm依存なし。
- esbuildは画面とサーバーを1つのモジュールにまとめるためだけに使用。
- `/` は鳩係の入口、`/demo` はブラウザ内だけで動くサンプル、`/privacy` はデータの説明。
- `/api/*` は認証された鳩係専用。Webhookは署名検証でLINEから受信します。月間当番表はLINEのFlex Messageで共有します。

## 開発

Node.js 22以降。

```powershell
npm ci
npm run dev
```

`http://127.0.0.1:8787/demo` で画面を試せます。`/` はローカル開発時のみ認証を省略した空の管理画面です。ローカルD1は `.local/d1/` に保存します。開発環境からLINEに送信する資格情報は設定していません。

```powershell
npm test
npm run build
```

テストはMiniflareのWorkers実行環境とD1を使い、LINEへの通信だけを模擬します。未認証アクセスの拒否、CSRF、OAuthのstate・nonce・audience、Webhookの署名・再配信・イベント順序、当番表の保存競合、グループの紐づけ、送信失敗と同じキーでの再試行、当日朝8:00の配信を検証します。

本番・ローカルとも、現在インストールしたworkerdが対応する `2026-07-30` を互換日付に使用します。初回デプロイ時にCloudflareがクライアント上の日付 `2026-11-09` を未来の日付として拒否したためです。互換日付を進めるときは、workerd/Miniflareも更新して再検証してください。

### Workerのシークレット

以下をCloudflareのWorkerシークレットとして登録します。ブラウザに返したり、コード・コミット・ログに含めたりしないでください。

- `LINE_CHANNEL_SECRET`：Messaging APIのチャネルシークレット。
- `LINE_CHANNEL_ACCESS_TOKEN`：このBot専用の長期アクセストークン。
- `LINE_LOGIN_CHANNEL_ID`：同じmonetta配下に作成するLINEログインチャネルのID。
- `LINE_LOGIN_CHANNEL_SECRET`：そのログインチャネルのシークレット。
- `BOOTSTRAP_OWNER_ID`：最初の責任者の、同プロバイダー内のLINEユーザーID。

最初の責任者のログインで管理者を登録し、初期登録を消費済みにします。以後の権限変更はアプリから行います。`DEV_MODE` は本番に設定しません。コード側でもlocalhost以外では開発用の認証省略を拒否します。

### LINE側の設定

1. 公式アカウントのMessaging APIをmonettaと連携。
2. グループへの参加を許可。
3. Webhook URLを設定し、「検証」が成功することを確認してWebhookを有効化。Webhookの再送も有効化。
4. LINE Official Account Managerの既定の応答メッセージをオフにする。あいさつメッセージもオフにすれば、Webhookからの歓迎メッセージと重複しません。
5. LINEログインチャネルをウェブアプリ用に設定し、上記のコールバックURLを登録。部員のメールアドレス取得権限は不要。
6. 次の鳩係もログインできるように、運用開始時にはログインチャネルを公開する。

### 配置と定期実行

`deploy/metadata.json` にシークレット以外のバインディングとログ設定があります。`dist/worker.mjs` とこのメタデータをmultipart形式でWorkers APIへアップロードします。`keep_bindings: ["secret_text"]` により既存のシークレットを維持します。

初回は `migrations/0001.sql` をD1に適用します。同SQLは初回セットアップの再実行が可能です。運用開始後の変更では新しい番号のマイグレーションを追加し、既存データを消さない形で適用してください。

Cronは `* * * * *`（毎分、UTC）を1つ登録します。Workerが日本時間に変換し、当日の通知を08:00〜08:14だけ処理します。ほかの時刻は共有送信の受付再確認と実行状況の記録を行います。

コード更新のロールバックとD1の復元は別です。CloudflareのD1 Time Travelや、アプリの「データを書き出す」で取得したバックアップを利用し、復元作業は技術担当が行います。バックアップにはLINEユーザーIDが含まれます。

## 配信のルール

- 下書き保存だけではLINEへ送信しません。「LINEに送る」の確認操作で共有します。
- 未設定の日がある場合は共有できません。「お休み」を明示的に選べます。
- 共有先は、公式LINEをグループに招待し、「配信・設定」でグループ名を確認して確定します。ログインした鳩係が参加しているグループが候補に表示されます。グループへの連携用メッセージは不要です。
- 当番表の版と送信本文は、送信前にD1へ固定して保存します。LINE受付後に配信対象の版を切り替えます。
- LINEの受付結果が不明なときは、同じ `X-Line-Retry-Key` で再試行します。再確認中はその月の編集を止めます。23時間を過ぎた共有要求は自動再試行を停止します。
- 朝8:00時点で共有されていた担当だけが自動通知の候補です。朝8:00以降の共有で担当が変わった場合は、新しい担当者に遅れて自動送信しません。鳩係が本人に連絡します。
- 通知は日付・担当者で一意。アプリの再起動やCronの再実行でも同じリトライキーを維持します。
- ブロック・部員登録解除・担当候補からの除外がある人には、新たな自動通知を送りません。共有済み表の担当を変えるには、当番表を更新して再共有します。
- 「LINE受付済み」は端末への到着や既読を保証しません。08:15までに受付を確認できなければ、アプリは個別連絡を案内します。
- プラットフォーム全体が停止した際の外部監視通知はありません。サークルの連絡手段で当番表を確認できるようにしてください。

## 鳩係の毎月の手順

1. 「メンバー」で追加された部員を確認し、当番表に載せる名前で登録。
2. 当番表の月を翌月に進める。
3. 日付をタップして担当者を選ぶ。担当回数を見ながら調整。
4. 担当しない日は「お休み」を選ぶ。
5. 「LINE共有」で当番表・共有先・通数を確認し、「この当番表をLINEに送る」を押す。
6. 変更時も同じ手順で更新版を共有。当日08:00以降の交代は、新しい担当者へ直接連絡。

引き継ぎは、新しい鳩係をメンバー登録してから「配信・設定」の権限を「鳩係」または「責任者」に変更します。実際に新しい人がログインできることを確認してから、以前の人の権限を外してください。LINE公式アカウント・LINE Developers・Cloudflareの管理者権限の引き継ぎも別途必要です。

## 運用開始前の確認

- テスト用LINEユーザーが友だち追加し、メンバー一覧に現れる。
- テストグループに月間当番表のカードが届き、担当者名と色を確認できる。
- テスト担当者の個別トークにだけ通知される。
- 管理画面を閉じていても朝8:00のCronが実行される。
- サークルの正式なグループに既存の公式アカウントがいない（1グループに参加できる公式アカウントは1つ）。

実機検証の完了までは、本番の当番表を共有しないでください。

## 初回接続の確認結果

- 本番URLの公開、LINEログイン、責任者の初期登録を確認。
- 実際のD1への保存・再読み込みを確認し、試験入力は空へ戻した（2026年11月の下書きバージョン2、共有なし）。
- LINE DevelopersのWebhook検証が成功。Webhook利用・再送とグループ参加を有効化。既定の応答・あいさつは無効化。
- 本番アプリからLINEのメッセージ通数APIを取得できることを確認。
- Cloudflare Cronの実行がD1に記録されることを確認。
- 部員登録と実際のグループ共有・個別メッセージの到着は、利用者によるBotへの「登録」送信とグループ招待の後に確認する。
